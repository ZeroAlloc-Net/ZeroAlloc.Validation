This page collects the breaking changes shipped in ZeroAlloc.Validation 2.0.0. Each section
covers one change: what changed, why, and what to do about it.

## `ZeroAllocOptionsValidationExtensions` moved out of the global namespace

`ValidateWithZeroAlloc()` is generated by `ZeroAlloc.Validation.Options` onto a static class
named `ZeroAllocOptionsValidationExtensions` (and, for options models that are not public,
`InternalZeroAllocOptionsValidationExtensions`). In 1.x both were emitted into the global
namespace, so any project using this generator shipped a public type with that name sitting in
the one namespace every consumer shares — the same slot a completely unrelated library, or your
own code, could just as easily land a type in.

In 2.0.0 both classes are emitted into `ZeroAlloc.Validation.Options`, the namespace
`ZeroAllocOptionsValidator<T>` already lives in.

### What to do

If your code called `ValidateWithZeroAlloc()` relying on it being in the global namespace, add:

```csharp
using ZeroAlloc.Validation.Options;
```

to any file that calls `ValidateWithZeroAlloc()`. Nothing else about the call changes — the
method name, its signature, and its behavior are unchanged.
