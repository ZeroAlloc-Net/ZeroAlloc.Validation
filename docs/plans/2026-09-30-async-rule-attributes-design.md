# Async custom rule attributes: design

**Issue:** #202. **Status:** built as the maintainer approved in the issue on 2026-09-30.
**Builds on:** #196, `docs/plans/2026-09-25-custom-rule-attributes-design.md`.

## Public API

```csharp
[AttributeUsage(AttributeTargets.Property, AllowMultiple = true)]
public abstract class AsyncValidationAttribute<T> : ValidationAttribute
{
    public abstract ValueTask<bool> IsValidAsync(T value, CancellationToken ct);
}
```

- **A separate base class.** `ValidationAttribute<T>` gains no member, so no existing rule breaks.
- **Additive support type.** `ZeroAlloc.Validation.Internal.AsyncFailureBuffer` is added. It works like `FailureBuffer`, but it is not a `ref struct`, so it can live across an `await`.

## Which models validate asynchronously

A model validates asynchronously when either of these holds, decided by `RuleEmitter.RequiresAsync`:
- A rule the validator emits is an `AsyncValidationAttribute<T>`.
- A nested or collection `[Validate]` model validates asynchronously, transitively. A cycle is decided by its first visit.

Other rules:
- **Only emitted rules count.** A rule dropped for another diagnostic does not count, so the async body always awaits something and never raises CS1998.
- **`[ValidateWith]` does not count.** Its validator is not generated here. An async body still calls its `ValidateAsync`.
- **Other models are unchanged.** Every model without async rules generates byte-identical output. This was checked against every validator in the repository's test projects, samples and benchmarks.

## Emission

For an async model, the generated file contains:
- **`__ValidateAsyncCore`.** A private `async ValueTask<ValidationResult>` method whose body `RuleEmitter.EmitValidateBody` emits in async mode:
  - Rules run in declaration order. Each async rule is written as `!await __Rule_X_i.IsValidAsync(value, ct).ConfigureAwait(false)` in the same `if` / `else if` chain as the sync rules. So `When`, `Unless`, stop-on-first-failure, `Message`, `[RuleMessage]`, `ErrorCode` and `Severity` work unchanged.
  - Every nested and collection validator is awaited through `ValidateAsync`. A span or a `ref` local cannot live across an `await`, so a `List<T>` is walked by index. `[CustomValidation]` spans go to `AsyncFailureBuffer.AddRange`.
- **The `ValidateAsync` override.** It calls the core directly, or through the model's async pipeline behaviors.
  - The behavior chain uses `static` lambdas, so the core is `static` unless it reads nested validator fields.
  - A behavior on a model with nested validators already fails with CS8821 for sync models. That is tracked in #294.
- **The call-warning probe.** It compiles the async body as an async method, so ZV0032 mirrors warnings on async rule calls too.

## What sync `Validate` does

**Decision: it always throws `NotSupportedException`**, naming `ValidateAsync`. The issue listed three options.

**(b) Skip the async rules, and document it.** Rejected. The maintainer ruled that sync `Validate` must never skip async rules silently.

**(a) A compile-time diagnostic wherever sync `Validate` is reachable.** It cannot be complete:
- `Validate` is a public virtual on `ValidatorFor<T>`, and callers reach it through the abstract type, generics, DI and nested validators.
- A diagnostic would miss most of those paths, and a missed path would skip the rules silently.

**(c) Throw.** The only option with no silent path.
- It throws whatever the model's values are, even when every async rule would have been skipped by `When`. So the first test finds it, not production.
- `Validate`'s sync pipeline behaviors would only wrap the throw, so none are applied.

**On top of the throw, one statically known sync-only path is a compile-time error.** Options validation is `IValidateOptions<T>`, which is synchronous:
- ZV0034 reports `ValidateWithZeroAlloc()` on an `OptionsBuilder<T>` of an async model, at the call.
- The main generator reports it, because only the main generator knows which models are async. It recognises the call by name, since the extension is generated by the Options generator and cannot be bound.

**A possible follow-up, needing the maintainer's call:** a diagnostic at direct `validator.Validate(model)` calls whose receiver is statically an async model's validator. It would find some misuse at compile time, but never all of it, so the throw stays.

## Integrations

- **ASP.NET Core.** The filter already awaited `ValidateAsync`. It now passes `HttpContext.RequestAborted`, so an aborted request cancels async rules and async behaviors.
- **Options.** See ZV0034 above. `ZeroAllocOptionsValidator<T>` is unchanged. A hand registration reaches the throwing `Validate`.
- **Inject.** Registration only; no call to `Validate`, so nothing changes.
- **Testing.** `ValidationAssert` takes a `ValidationResult`, so it works with `await ValidateAsync(...)`.

## Cancellation

The token reaches every async rule and every nested validator. The validator does not check it between rules. The rule decides how to honour it.

## Tests

- **Runtime:**
  - declaration order across sync and async rules
  - When and Unless, including that a skipped rule is not called
  - property-level and model-level stop-on-first-failure
  - message, error code and severity precedence
  - cancellation
  - nested, `List<T>`, array and null-element models
  - the throwing sync `Validate`, directly and through `ValidatorFor<T>`
- **Allocation:** the valid path with a synchronously completing rule allocates nothing.
- **Generator:**
  - the emitted shape
  - ZV0020, ZV0021, ZV0023 and ZV0026 with async rules
  - ZV0032 on an async call
  - `[CustomValidation]` of every return type in an async body
  - async behaviors
  - transitive and cyclic models
  - ZV0034 in all three call forms, and its caching
  - Every test compiles the output with no errors and no warnings in generated code.
- **Integration:**
  - ASP.NET Core returns 422 for an async rule failure.
  - The AOT smoke covers async rules, nested and collection models, the throw and cancellation.
  - PackSmoke covers an async rule against the packed package.
